# 検証方法と記録

## 同じ検証を実行する

```bash
export UV_CACHE_DIR="$PWD/.uv-cache"
uv sync --locked
uv run --locked python scripts/verify.py
```

検証スクリプトは Ruff、整形の確認、pytest を順に実行します。
各終了コードと出力、Python とパッケージの版を `artifacts/verification.json` に保存します。
このファイルは実行ごとに更新され、Git の対象外です。

## 検証の種類

| 種類 | 実際に行うこと | 保証しないこと |
| --- | --- | --- |
| 基本の入出力 | Python プロセスを起動し、標準出力、標準エラー、保存ファイル、終了コードを確認 | 任意形式の入力への対応 |
| OR-Tools | CP-SAT を実行し、最適値と割り当て制約を確認。解なしと不正入力も試す | 大規模問題の性能 |
| ローカル実行 | `local.Application` の子プロセスを実際に起動し、履歴、再実行、条件比較を確認 | クラウドランタイムと同一の動作 |
| クラウドの送信前検証 | 実物の SDK の型、マニフェスト、署名で検査し、通信部分をテスト用の代用品にする | 認証、権限、配備、課金、クラウド上の実行と判定 |
| ネットワーク隔離 | pytest と Python 子プロセスの接続を拒否し、uv はオフライン実行 | OS 全体の通信を禁止する仕組みではない |

検証では認証用の環境変数を子プロセスへ引き継ぎません。
クラウドのプレビューでは Client を作成しないことも確認します。
通常の `pytest` でも通信を拒否する fixture が有効ですが、一括スクリプトは SDK が起動する Python 子プロセスにも接続拒否を引き継ぎます。
