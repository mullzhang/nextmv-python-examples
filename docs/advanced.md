# 次に試す機能

このページの機能は説明のみで、自動テストや検証コマンドから実行しません。

## 外部実行とローカル結果の同期

**外部実行**は、Nextmv Cloud の外で計算した結果をクラウドの実行として記録する仕組みです。
既存のバッチ処理や別の計算基盤の結果を、同じ実験や比較の対象として扱う用途があります。
`ExternalRunResult` などの結果モデルと外部実行用の API を使います。
モデル自体をクラウドで再計算する操作とは区別します。
[公式の外部実行ガイド](https://docs.nextmv.io/python-sdk/cloud/track-external-runs/) に手順があります。

ローカルの SDK 履歴を持つ場合は `local.Application.sync` が候補になります。
入力、出力、指標をクラウドへ送るため、ネットワーク接続と権限が必要です。
このリポジトリのローカル編は同期を呼びません。
次に追加するなら、まず同期する実行 ID を1件に限定し、送信される入力と結果の範囲を確認する例が適しています。
[ローカル実行の同期](https://docs.nextmv.io/python-sdk/local/sync/) を参照してください。

## シャドーテストとスイッチバック試験

**シャドーテスト**は、対象の実行に応じて候補モデルにも入力を渡し、結果を比較する仕組みです。
候補の出力をそのまま本番の意思決定として採用することとは分けて運用します。
同じ入力で追加の実行が発生するため、監視するインスタンス、対象期間、停止条件を決めてから利用します。
このリポジトリには、継続して作動する試験を作るスクリプトは含めていません。
[公式のシャドーテストガイド](https://docs.nextmv.io/python-sdk/cloud/run-shadow-tests/) を参照してください。

スイッチバック試験は、本番側で使う条件を時間区間などに応じて切り替えて評価する機能です。
保存済み入力に対する比較だけでは捉えにくい実際の運用を扱うため、バッチ実験や受け入れ試験の次の段階になります。
詳しくは [Cloud の機能一覧](https://docs.nextmv.io/python-sdk/cloud/) から各機能のガイドを参照してください。

## 出力の可視化と独自形式

`Output.assets` と `Asset` を使うと、解を説明する図などを出力に添えられます。
最初に `solution` と `metrics` の意味をそろえ、その後で図を追加すると、数値と図の整合性を確認しやすくなります。
[出力ガイド](https://docs.nextmv.io/python-sdk/modeling/output/) に可視化用の例があります。

複数ファイルの例では CSV と JSON を使いましたが、独自の `DataFile.loader` と `SolutionFile.writer` で別形式も扱えます。
Excel のように追加ライブラリを使う場合は、読み書きに必要な依存関係も固定します。
次の例としては入力の型検証を伴う Excel の読込などが考えられます。

## 実行基盤と運用機能

| 機能 | 追加するときに確認すること |
| --- | --- |
| 実行クラス | メモリ、計算時間、利用可能なクラス、料金。クラウドの現行仕様を参照する |
| キュー | 優先度、同時実行数、待ち時間と計算時間の区別 |
| Secret Collections | 秘密情報をモデルに渡す仕組み。ログや結果に書かない設計 |
| SSO | API キー方式とは異なる認証とセッションの管理 |
| 実行の複製 | 元の入力を再利用して条件を変える際に、実際に使った版とオプションを記録する |
| 実行の比較 | 同じ指標名、単位、入力条件で結果を比較する |
| アンサンブル | 複数の実行から結果を選ぶ規則と、追加実行の費用を明確にする |

これらの現行 API は [Cloud ガイド](https://docs.nextmv.io/python-sdk/cloud/) と [SDK ソース](https://github.com/nextmv-io/nextmv-py) で確認できます。
具体的な料金や利用上限はアカウントにより異なるため、このリポジトリでは固定値を記載していません。
